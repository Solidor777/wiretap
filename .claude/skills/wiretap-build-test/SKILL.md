# Wiretap build and test

Current-state reference; verify against code before relying on a detail. Core context: `wiretap-codebase-core`.

## npm scripts (from `package.json`)

`build` (vite build), `build:e2e` (vite build --mode e2e), `check:build` (`node scripts/check-module-build.mjs`: fails when a file `module.json` names under `esmodules` or `styles` does not exist), `check:release` (the same script with `--release`: also fails when `dist/` holds any file other than `index.js`, `index.js.map` and `style.css`, and names the extras), `dev`, `test` (vitest run), `test:watch`, `test:e2e`
(playwright test; `:headed`, `:ui`), `eslint`, `eslint-fix`, `server` (tsx watch), `server:start` (tsx), `server:mcp` (tsx, `--mcp-only`),
`typecheck` (tsc -p server/tsconfig.json), `stylelint`, `stylelint-fix`, `foundry:start` (`node scripts/e2e-foundry-server.mjs --standalone`).

## Rules

- Tests that start a server on a port take it from `reservePort()` of `tests/portPool.js`, never from the OS: a port
  reserved by listening on port 0 and releasing it comes from the dynamic range that outbound client sockets share
  (Windows 49152 to 65535), and another worker's connection could take it before the real bind (`EADDRINUSE`, MEASURED
  under four concurrent vitest runs). The pool is 32000 to 48999, one 300-port slice per vitest worker
  (`VITEST_POOL_ID`), each candidate bound-checked; `tests/unit/portPool.test.js` fails when a port leaves the pool or
  repeats. Direct `net.createServer().listen(0)` stays only where the test holds the port (`occupyPort`, `SuperviseServer`).
- No e2e wait inside a loaded page longer than 1000 ms (`expect.poll`, `waitForFunction`, `toPass`, explicit
  `timeout:`). A longer wait is a defect to fix. World boot, login, reload, build and per-test limits are exempt.
- `tests/e2e/writeTools.spec.js` covers the write tools on throwaway `Wiretap E2E ` documents: it opens gates only through its
  `openGate` helper (restored in `afterEach`), registers page hooks (`preUpdateActor`, `preDeleteActor`) and removes them
  in `finally`, and records every created document on the running list. See `wiretap-writes` for what each test asserts.
- e2e needs Foundry on `:30000` with the module enabled and a GM user (see `tests/e2e/users.js`); Playwright starts or
  reuses it through `node scripts/e2e-foundry-server.mjs`. Read references/e2e-foundry-server.md before changing the
  launcher, its defaults or its overrides.
- Tests that write files inject a root under the gitignored `test/tmp/` (`mcpConfigFile` uses a unique
  `<timestamp>-<pid>-<counter>` root per test and asserts it does not exist yet, so a stale scratch fails loudly) or mock `node:fs`; no test and no product code calls a deletion API (`rm`, `unlink`, `rmdir`, sync forms included) or imports `rimraf` or `del`, and only `server/backups.ts` imports `trash` (`tests/unit/noPermanentDelete.test.js` scans `server/`, `shared/`, `src/`, `scripts/` and `tests/`; its patterns are built from joined strings so the file does not match itself). Product code never reads
  a test-only env var. Stale files in `test/tmp/` stay until removed by hand.
- Build output goes to `dist/` for both builds (`scripts/lib/buildOutput.mjs`, used by `vite.config.mjs`; `module.json` points at `dist/index.js` and `dist/style.css`), `emptyOutDir` stays false and nothing deletes files. The e2e build (`--mode e2e`, also compiled with the probe flag) emits hash-free names (`index.js`, `TerminalConnection.svelte.js`, `registerProbe.js`, `style.css`, maps), so each build overwrites the last and nothing accumulates; the production build has no dynamic import and emits only `index.js`, `index.js.map`, `style.css`. The e2e global setup runs `build:e2e` and then `check:build`. A production build after an e2e one leaves the e2e-only chunks (`registerProbe.js`, `TerminalConnection.svelte.js`, their maps) in `dist/` unreferenced: packaging runs `npm run build`, then `npm run check:release`, and the extras are recycled with `trash` first. Test code is not in the production `index.js` (the probe import is dead-code eliminated). `tests/unit/buildOutput.test.js` covers the output directory, the hash-free names, the production naming, the manifest paths, the missing-file check and the release check (scratch roots are created with `recursive: true` under the gitignored `test/tmp/`, so a clean checkout works).
- Lint/format rules live in `eslint.config.js`, `.stylelintrc.json`; `:global` is forbidden.
- Run `npm test`, `npm run typecheck` and `npm run eslint` before claiming a change is verified; report the output.
